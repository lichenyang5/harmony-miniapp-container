# 面试演示讲解稿

项目：HarmonyOS 多厂商 H5 小程序容器集成与原生能力桥接。

这份稿子配合真机录屏使用。第三方小程序的页面、算法和业务数据不属于本项目的原创成果；个人贡献重点为新宿主、独立 HAR 接入、协议能力联调、导航生命周期接入、构建和验收。

## 开场（约 20 秒）

这个项目是在一个新的 HarmonyOS 应用里，接入已有的多厂商小程序 SDK。我主要负责 ArkTS 宿主、独立 HAR 构建与消费、导航和生命周期接入，以及选定能力的联调与真机验证。下面通过两个真实业务小程序，展示它从打开、操作，到退出和再次进入的完整过程。

## LINE：天气查询与偏好恢复

### 进入业务

这里打开的是 Yahoo! 天气的真实 LINE 小程序，宿主使用 LINE WEB 模式。这次业务浏览没有要求登录，所以我只声明业务浏览通过，不把它描述成 LINE 账号认证已经完成。

### 搜索和保存

我使用公开测试邮编 1500002，选择东京涉谷区，不读取手机的真实位置。搜索结果和天气数据都来自远端业务。保存涉谷后，原有的新宿偏好也继续保留。

### 日期操作与刷新

现在切换明日和今日预报，验证真实页面内的状态变化。再使用宿主刷新，确认天气页面和测试地区能够恢复。这里展示的是业务承载和恢复行为，天气服务和数据本身不是我开发的。

### 返回与重开

这个页面的日期切换没有建立可后退的网页历史，因此宿主返回会退出到目录。重新打开后，新宿和涉谷偏好仍保留，最后通过关闭按钮退出。我不会把这个结果说成账号云同步或全部 LINE 小程序都兼容。

## VK：参数计算与业务详情

### 进入业务

这里是第三方 VK 壁纸用量计算器，复用之前在官方页面建立的登录态。视频不包含账号、密码或验证码输入；也不把已有登录态复用描述成一次全新登录验收。

### 两步表单

先使用虚构测试房间，长 400、宽 300、高 270 厘米，门窗都设置为零。下一步选择内置纯色壁纸，卷宽 53、卷长 1005 厘米，保持无对花模式，然后执行计算。

### 结果与裁切图

这组参数在当前远端版本里得到 10 卷、28 条的结果。打开墙面详情，可以看到二维裁切图和卷号。计算算法和业务页面属于第三方，我负责的是在 HarmonyOS 容器里正确承载它们。未通过的可选 3D 页面不列入本次展示。

### 返回、关闭与历史恢复

这里分别使用手机系统返回和宿主返回，回到业务结果页，说明返回事件接入了容器的导航控制。关闭后回到宿主首页，再次打开并进入历史记录，可以恢复刚才的计算结果。此前验收日志也确认，关闭时会释放 WebView 和 SDK 会话。

## 收尾（约 20 秒）

项目现在既有真实业务演示，也有 API 测试入口，后者用于单独展示 LINE 扫码、VK 扫码和振动。构建与交付方面，宿主最终消费独立 HAR，已有 44 项迁移回归和选定真机验证。这些证据对应具体范围，不代表全部平台 API、所有小程序或长期稳定性都已通过。

## 面试追问速答

| 追问 | 回答要点 |
| --- | --- |
| 哪些是你做的？ | 宿主、启动校验、HAR 构建消费、签名隔离、导航接入、诊断和联调验收；已有 SDK 协议和会话框架需区分来源。 |
| 这是不是普通网页套壳？ | 业务录屏说明真实网页承载；原生扫码、振动的桥接能力用另外的 API 入口和验收记录证明，不能仅凭天气网页证明。 |
| 为什么两边返回效果不同？ | VK 子页接入了业务导航；LINE 天气日期切换是页内状态，没有可回退网页历史时按宿主规则退出。 |
| 关闭重开能恢复什么？ | 当前设备上已验证的天气偏好、计算历史；未验收账号云同步或长期持久性。 |
| 性能如何？ | 没有可用于优化对比的基准测量，远端加载受网络和平台影响；不拿单次 API 耗时或剪辑后视频时长当性能指标。 |
