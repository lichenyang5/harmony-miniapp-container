# 鸿蒙小程序容器实战 06 真实业务验收与面试展示

扫码和振动跑通后，项目已经有了原生桥接证据。但实际使用小程序时，还会填写表单、进入详情、返回、关闭，再打开看状态是否保留。

因此，我在 API 测试入口之外接入了一个 VK 计算工具和一个 LINE 天气服务。本篇记录如何选择操作路径、分层验收，以及将结果整理成可下载的展示材料。

## 选择操作结果明确的业务

选择应用时，我优先考虑能观察到具体输入和输出的流程。VK 壁纸用量计算器可以核对参数、卷数和二维图；LINE 天气可以核对地区、预报日期与保存后的偏好。

它们分别覆盖不同交互，同时避免为了演示扩展到支付、消息发送和其他不必要的业务。

当前目录保留四个入口：两个真实 API 测试应用，加上这两个业务应用。新增入口没有放宽官方 URL 与 ID 的检查规则。

初选的一个 VK 应用曾只显示加载态，没有作为业务成功保留。筛选业务时，SDK 识别到身份只是中间状态，仍要等页面和选定操作实际完成。

## VK 用确定参数核对真实结果

业务选用 `54638228`，即壁纸用量计算器。测试房间使用以下参数：

| 参数 | 数值 |
| --- | --- |
| 房间长宽高 | 400 × 300 × 270 cm |
| 门窗数量 | 均为 0 |
| 壁纸卷宽 | 53 cm |
| 壁纸卷长 | 1005 cm |
| 图案 | 纯色、无对花 |

页面实际显示 10 卷、28 条、铺贴面积 37.8 m²；二维墙面详情显示 400 × 270 cm、8 条。

这些数字用于确认输入、结果页和重开记录对应同一次操作。计算算法由第三方业务提供，不能据此把壁纸计算功能归为宿主原创。

演示随后验证宿主顶部返回与系统返回，都能从二维详情回到结果页；关闭后回到宿主首页，再次打开，通过历史记录恢复同一结果。

录制时房间名加入 `InterviewDemo` 标记，便于区分测试记录。业务阶段复用已有官方登录态，没有为了镜头清除账号状态或制造一次新的登录验收。

可选 3D 预览虽然能打开页面，但没有显示模型，因此没有纳入成功流程。一个入口能打开与其中每个功能都可用，需要分别判断。

## LINE 检查搜索与偏好恢复

LINE 使用 Yahoo! 天气入口 `2009013997-MX3EzKQv`，以 WEB 模式加载。

初次业务验收使用公开邮编 `1600022` 搜索新宿，保存地区后切换今日与明日，验证刷新和重开后偏好仍在。

录制时又使用 `1500002` 新增涉谷，同时保留新宿。这样可以从镜头中看到搜索、选中、保存和恢复的连续变化，无需使用设备真实位置。

本次页面未要求登录，所以保存结果只说明当前环境的业务偏好能够恢复。它不证明 LINE 账号认证或云同步。

日期切换也没有建立可回退的网页历史。当前顶部返回和系统返回从根页退出容器，这是本次记录的实际行为。

## 将业务动作与容器状态对应

我为业务流程选择了可观察的检查点：

```text
打开 → 看到业务首页
操作 → 得到远端实际结果
返回 → 回到期望页面或退出根页
关闭 → 回到宿主并执行资源释放
重开 → 创建新会话并检查业务状态
```

页面结果与会话日志一起使用。页面说明用户看到了什么，日志说明是否经过预期的创建、返回和关闭路径。

日志不能代替页面操作，页面截图也不能单独证明底层资源释放。两种证据互相补充，更容易定位问题。

## 把测试分成不同层次

项目的检查结果按以下层次记录：

| 层次 | 可以支持的结论 |
| --- | --- |
| HAR 与 HAP 构建 | 当前工具链下能够编译、打包 |
| 44 项迁移回归 | 指定逻辑和协议在真实 SDK 加平台替身环境中通过 |
| ArkTS 测试编译 | 测试代码能够编译，未等同于设备执行 |
| 真机 API 操作 | 选定系统能力与网页回包实际可用 |
| 真机业务操作 | 选定应用的具体业务路径可以完成 |
| 视频与日志 | 保存本次操作证据，便于复看和讲解 |

44 项回归由继承测试与新增迁移测试组合，不是本次独立新增 44 项，也不是 44 个设备用例。原 SDK 其他套件仍有缺失引用和旧断言等失败，单独保留记录。

同样，十轮快速挂载关闭没有逐轮等待完整业务加载，不能称为十轮完整业务压测。长期内存、断网恢复和真机迟到回包场景仍是下一阶段工作。

## 录屏保留连续操作和剪辑说明

本次通过临时 Debug 录制助手调用系统公开录屏接口，经系统录屏提示后开始录制。麦克风关闭，结束后助手从源码移除，正常签名 HAP 已重新构建并安装。

LINE 原片约 164 秒，VK 原片约 306 秒。成片裁去状态栏和调试区域，省略空闲等待，对部分加载作 2～4 倍加速，导航片段作局部慢放，并在字幕与剪辑清单中说明。

所有业务画面来自真机操作。剪辑后的 74 秒和 123 秒用于控制展示长度，不代表加载性能。

输出为 H.264、1080p、30 fps 的静音字幕 MP4。讲解稿单独保存，现场可以按章节暂停展开技术细节。

## 让展示材料可以离线带走

完整包中包含两段 MP4、离线播放页、章节信息、封面、SRT/VTT 字幕、讲稿和说明。播放页没有外部依赖，支持按平台和章节查看对应讲解要点。

视频与 ZIP 作为 [GitHub Release 附件](https://github.com/lichenyang5/harmony-miniapp-container/releases/tag/showcase-v1.0.0) 分发，源码仓库保存播放页和制作工具。这样日常代码提交不必携带大视频文件。

发布时核对了 ZIP 中的 13 个文件，并在 Release 发布后，不带认证下载四个附件，确认大小与 SHA256 一致。

GitHub 自动生成的 Source code 压缩包不含视频。使用时应选择 `miniapp-interview-showcase.zip`，完整解压后打开 `index.html`，也可直接播放两段 MP4。

成片已完整解码并核对关键帧。离线页面完成了资源路径与交互逻辑检查，但受内置浏览器本地 URL 策略限制，尚未记为浏览器实播通过；面试前仍应在本机 Chrome 或 Edge 完整播放一遍。

## 现场讲解围绕工程决策展开

展示业务时，我会用一句话说明第三方应用的用途，把时间留给容器如何承载它：为什么使用独立 HAR，为什么区分 WEB 和 CLIENT，返回如何判断边界，关闭后如何处理会话。

如果面试官关注原生桥接，就切到 API 测试入口说明扫码成功、取消重试和错误映射；如果关注工程化，就打开构建与回归入口。

当前系列能够支持的个人职责是新宿主、独立 HAR 集成、构建与签名隔离、诊断入口、导航生命周期接入和验收。原 SDK 的协议与会话框架，以及第三方页面的业务算法，分别说明来源。

后续最值得补强的是原生扫码与振动的短演示、干净环境构建，以及异常和稳定性测试。每增加一项，都应对应一个具体场景和可以复核的结果。
