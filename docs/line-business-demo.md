# LINE 真实业务小程序演示

验证日期：2026-11-16。环境：签名 Debug HAP、独立打包 HAR、API 26 真机、`LineMode.WEB`。

## 选定应用与接入

- 名称：**Yahoo! 天气与灾害（Yahoo!天気・災害）**。
- 宿主目录第四项：**LINE · Yahoo! 天气**。
- LIFF ID：`2009013997-MX3EzKQv`。
- 配置入口：`https://miniapp.line.me/2009013997-MX3EzKQv`，此具体 ID 来自原工程目录，已在本工程真机打开对应天气页面。
- [Yahoo! 官方公告](https://weather.yahoo.co.jp/weather/notice/weather/20260820.html)介绍了 LINE 小程序入口及地区搜索；[官方使用说明](https://support.yahoo-net.jp/PccWeather/s/article/H000014991)提供别名入口 `https://miniapp.line.me/yjweather/home`。

宿主仍使用现有的 ID/官方 URL 校验规则，没有为了别名放宽启动范围，也没有将任意 H5 直接作为 LINE 小程序启动信息。

远端页面与天气服务属于第三方。本项目负责入口接入、WEB 容器承载、导航退出与验收，不宣称开发天气算法、数据或业务页面。此次未修改 SDK 厂商协议；仅将宿主 Debug 扫码面板限定在原 API 测试入口，业务页不添加该面板。

上表均为本次已完成的步骤。三个会话分别用于验证顶部返回、系统返回和关闭，不作为长期稳定性指标。测试截图与 UI 快照保存在忽略的 `.local/`，不提交账户或会话资料。

## 面试操作卡（约 2～3 分钟，不计加载等待）

1. 从宿主第四项打开 **LINE · Yahoo! 天气**，等待出现天气页面。本次可不登录浏览；不把页面可用描述成已登录 LINE。
2. 点击 **地域検索（地区搜索）**。输入公开测试邮编 `1600022`，等待“東京都新宿区新宿”候选出现并选中。不要点击 **現在地（当前位置）**。
3. 确认页面显示 **新宿区**。如果尚未保存，点击 **この地域を登録する（保存此地区）**；如果已有该地区则直接继续，不必删除已有偏好重演。
4. 点击 **明日（明天）**，展示展开的预报和逐小时数据，再点 **今日（今天）**切回。天气数值随远端更新，不设固定温度验收值。
5. 点击顶部“刷新”，等待业务页恢复，确认新宿区仍在。
6. 点击宿主顶部“返回”，确认回到宿主首页。本应用此次页内日期切换没有建立可返回历史，返回的预期是退出容器，与 VK 二维详情的页内回退不同。
7. 再次打开，展示新宿区偏好仍保留；点击顶部“关闭”，确认返回宿主目录。
8. 如需展示手机系统返回，可从天气根页再打开一次并按系统返回键，同样应回到宿主目录。

本次已实际操作“明日 → 今日”双向切换，并核对展开项与逐小时内容。搜索候选为异步返回，看到真实候选再点击。面试前检查网络与远端入口，并避免展示系统通知、个人资料及凭证。

## 面试讲法与简历补充

可用于简历：

> 接入真实 LINE 天气小程序，完成地区搜索、偏好保存、预报切换、刷新恢复及导航退出验证，将业务承载演示与原生扫码测试分开呈现。

## 当前限制

- 未验证 LINE 官方账号登录、授权、CLIENT 账号协议或多设备偏好同步。
- 未点击好友添加、消息发布、定位、订阅、支付等入口。
- 当前业务页的日期切换不等同于浏览器历史导航；不能宣称宿主返回能撤销所有网页弹层或页内状态。
- 本次是选定业务流程验收，不能推导出其他 LINE 小程序或全部 API 兼容。
- 远端天气页面和数据可能变化，需按当前 UI 复核。[面试展示包](../showcase/README.md)已有真机字幕录屏；录制版新增涉谷测试地区，保留新宿偏好，并明确标注等待剪辑。
